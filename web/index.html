We pulled the plug 10,000 times.

One power cut in a demo shows recovery working. It doesn't prove it. So the database runs on a simulated disk that behaves like a real one when the power fails: anything synced survives, but each write since the last sync may land, vanish, or be torn half-way through.

Each scenario runs random transactions, cuts the power at a random moment (often in the middle of a commit or a checkpoint), restarts, and checks the promises below. A checker that never fails might be broken itself, so you can also switch on one of four classic durability bugs and watch it get caught.

The promises being checked

Durability
Once COMMIT returns, the transaction survives any crash.
Atomicity
A transaction interrupted mid-commit is either all there or not there at all. Never half.
Integrity
After recovery, every B+ tree is structurally sound: keys sorted, balanced, sibling links intact.
Still works
The recovered database accepts new writes.
